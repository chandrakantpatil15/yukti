AUTHENTICATION FLOW (NOW WORKING):
===================================

SIGNUP FLOW:
1. User visits /signup
2. Enters email + password + company name (optional)
3. Frontend calls api.signup(email, password, companyName)
4. Backend creates tenant + user (email_verified = false)
5. Backend sends OTP to email via AWS SES
6. Backend returns { success: true, otp_code: "123456" } (dev mode only)
7. Frontend shows OTP code in green box (dev mode)
8. Frontend shows verification form

VERIFY EMAIL FLOW:
1. User enters OTP code from email (or from screen in dev mode)
2. Frontend calls api.verifyEmail(email, code)
3. Backend verifies OTP against yt_otp_codes table
4. Backend sets email_verified = true
5. Backend generates JWT token
6. Backend returns { success: true, token: "...", user: {...} }
7. Frontend stores token in localStorage
8. Frontend redirects to /onboarding

LOGIN FLOW:
1. User visits /login
2. Enters email + password (NO tenant_code needed!)
3. Frontend calls POST /api/v1/auth/login with { email, password }
4. Backend finds user by email (email is UNIQUE)
5. Backend checks email_verified = true
6. Backend verifies password
7. Backend checks tenant status = active
8. Backend generates JWT with tenant_id
9. Backend returns { success: true, token: "...", user: {...} }
10. Frontend stores token
11. Frontend redirects to /dashboard

JWT TOKEN STRUCTURE:
====================
{
  "user_id": "uuid",
  "tenant_id": 123,
  "tenant_code": "acme-corp-abc123",
  "email": "user@example.com",
  "role": "admin",
  "scopes": ["read", "write"],
  "iat": 1234567890,
  "exp": 1234654290
}

JWT is used for:
- Authentication (all protected routes)
- Tenant isolation (tenant_id in JWT)
- License enforcement (subscription checks via tenant_id)

IMPORTANT NOTES:
================

1. JWT Token = License Enforcement
   - JWT contains tenant_id
   - All protected routes validate JWT
   - Subscription middleware will check yt_subscriptions table
   - If subscription expired → 403 Forbidden
   - This protects your platform in customer-hosted deployments

2. Dev Mode vs Production
   - Dev mode (JWT_SECRET not set): OTP shown in API response
   - Production (JWT_SECRET set): OTP only sent via email
   - Check logs: docker-compose logs -f backend | grep OTP

3. Email Verification Required
   - Users CANNOT login without verifying email
   - This prevents fake signups
   - OTP expires in 10 minutes
   - Max 5 attempts per OTP

4. Database State
   - yt_users: email_verified column exists
   - yt_otp_codes: stores OTP codes with expiration
   - yt_subscriptions: tracks trial periods (for license enforcement)

TROUBLESHOOTING:
================

If signup fails:
- Check backend logs: docker-compose logs -f backend
- Check database: psql -U yukti -d yukti_finops -c "SELECT * FROM yt_users;"
- Check OTP table: psql -U yukti -d yukti_finops -c "SELECT * FROM yt_otp_codes;"

If OTP not sent:
- Check AWS SES configuration in docker-compose.yml
- Check email service logs in backend
- In dev mode, OTP should appear in API response

If login fails with "Please verify your email":
- User hasn't verified email yet
- Check: SELECT email, email_verified FROM yt_users WHERE email = 'test@example.com';
- Verify email first, then login

If JWT token invalid:
- Check JWT_SECRET matches between signup and login
- Check token expiration (24 hours)
- Check middleware logs
